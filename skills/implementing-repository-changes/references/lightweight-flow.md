# 簡易フロー

文書、コメント、誤字、表示文言、型注釈、テストだけの変更など、製品・設定の挙動を変えない局所変更で使用する。

1. 変更前に `git status --short --branch` を確認し、既存差分と競合しないことを確かめる。
2. 挙動変更がないことと影響範囲を明示する。外部仕様、DB、API、認証・権限、依存、feature flag、既存ユーザーの導線・表示順・初期値、通知・バッチに触れる場合は standard へ切り替える。
3. 原則として現在の checkout で最小差分を編集する。リポジトリ規則が worktree を要求する場合、または既存差分との競合がある場合は standard へ切り替える。
4. 文書リンク、構文、format、対象テストなど、変更に直接対応する最小の検証を行う。
5. 意図しない挙動差分が見つかったら停止し、standard として再分類する。
